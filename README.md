# Практика 2. Источники данных

Минимальный загрузчик двух источников для проекта по экологическому мониторингу.

## Файлы

- `ingest.py` — загрузка EEA и Open-Meteo, проверка ответов и запись журнала.
- `config.json` — период, страна, загрязнитель, координаты и погодные переменные.
- `requirements.txt` — библиотека для HTTP-запросов.
- `.gitignore` — исключает виртуальное окружение и локальные данные из Git.

## Установка и запуск в Windows CMD

```cmd
py -3.11 -m venv .venv
.venv\\Scripts\\activate.bat
python -m pip install -r requirements.txt
python ingest.py
```

Повторный запуск выполняется командой `python ingest.py`.

## Источники

- EEA: почасовые измерения PM10, Польша, январь 2022 года, проверенный набор E1a (`dataset = 2`). Фильтр по городу не задаётся: API получает подходящие ряды по всей стране. Конкретные станции Варшавы будут отобраны на следующем этапе по их идентификаторам и координатам.
- Open-Meteo: почасовые исторические погодные данные за тот же период для точки в Варшаве (52.22, 21.00), формат JSON.

EEA возвращает ZIP-архив с файлами Parquet. Open-Meteo возвращает JSON. Исходные ответы сохраняются без очистки и объединения.

## Результаты

- `data/raw/eea/` — исходные ZIP-архивы EEA.
- `data/raw/open_meteo/` — исходные ответы Open-Meteo.
- `data/meta/load_journal.sqlite` — журнал запусков, операций и реестр загруженных месячных партиций.

Перед сохранением проверяются HTTP-ответ и формат данных. Повреждённый либо пустой архив EEA не регистрируется как успешно загруженный. Файлы записываются через временный файл и публикуются после проверки. Повторный запуск пропускает партиции, файл которых существует и контрольная сумма SHA-256 совпадает с журналом. Для временных сетевых ошибок, HTTP 429 и ошибок сервера выполняются повторные попытки.
